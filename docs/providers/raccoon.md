# 小浣熊接入

2026-11-24 官网静态源码对照确认了 loopback 授权参数与积分账单分页别名。
账单兼容顶层和 `paging` 下的 `has_more/next_cursor/cursor`，
仍要求明确分页状态及游标推进，不从空账单推断已延期。
Web 的设备绑定与令牌刷新不等于桌面业务令牌契约；最终换票、推理接口
及初始化 GET 是否足以触发积分延期，本次仍缺官方调用链或实测证据。

在控制台添加「小浣熊」服务，点击「登录账号」，在新标签页打开的官网完成登录、
确认授权和验证码。官网通过本机 HTTP 回调把授权码交给代理，代理换取业务令牌，
保存账号、同步模型并查询积分。浏览器与代理需要运行在同一台电脑。

取消等待、授权超时、服务删除、停用或地址变更会终止尚未提交的授权。
每次授权使用独立随机 state 和本机端口；重复回调、重复轮询不会重复换票。
访问令牌和刷新令牌保存在本地账号库，不返回到控制台。此接入不读取官方桌面客户端数据。

三种入站接口（Chat Completions、Messages、Responses）均转换为小浣熊原生
OpenAI Chat Completions。保留消息、工具定义、工具结果和 `max_tokens`，
流中错误或不完整响应按网关既有规则处理，不重放结果未知的生成。
模型调用 ID、显示名、能力、Token 限制和积分倍率从官网目录读取，不内置旧模型清单。

令牌在请求前检查；长效令牌在当前有效期的六分之一后滚动续期，短效令牌提前
两分钟。确定的 HTTP 401 刷新后最多重试一次。刷新串行且条件写回，避免覆盖人工修改。
没有使用请求的账号可由每 12 小时额度更新触发续期，也可点击「刷新凭证」。

额度使用官方 `available_points`，保留小数精度。`daily_points` 是其中未过期每日
积分的合计，不能重复相加或视作每天午夜全部重置。根据
[官方积分规则](https://doc.xiaohuanxiong.com/zh-hans/saas-user/user_manual/office_app/points_rules.html)，
每日积分在 00:00 自动发放，免费版 300、升级版 500。当日未登录，这笔积分在
当天 24:00 失效；当天登录则保留至含发放日的第七天。后续登录不会继续延长旧批次，
同一账号跨 Web、桌面、移动端也不会重复发放。例如 11 月 20 日积分，当天登录后
有效至 11 月 26 日 23:59:59（北京时间）。

任务页支持「登录保留积分」，手动、一键和每日自动执行共用每账号每天的任务记录。
先查询 `/api/web/points/v2/bills`：当天 `daily_grant` 的 `grant_at` 和 `expire_at`
已经符合七天规则时记录「已完成」。否则访问官网会话初始化使用的 `user_info` 和
`office/v3/setting_info`，再查询积分批次；只在当天批次实际到期时间确认后记录成功。
任务不将已自动发放的积分重复记录为新奖励，不主动申请首次登录奖励，不强制每日
刷新令牌，不模拟设备绑定或心跳。正常令牌续期和余额查询不能单独作为积分延期凭据。

账单核对最多读取一百条明细；缺少当天批次、到期时间未延长、跨日或核对失败时
记录「结果未知」，不自动重放当天动作。此时可从任务页或服务详情打开官网工作台核对。
自动任务需要代理进程在配置的执行时间运行，积分发放、延期和扣费仍以官网记录为准。

账号可能同时持有每日积分与购买积分，预设费用类型为「未知」。
`auto` 不会因为积分余额大于零就认定请求免费；按自己的账号情况明确选择费用类型。
