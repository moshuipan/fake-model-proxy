## 1. 交付顺序

先按公开协议打通一次真实工具调用，再扩大后端数量和自动化。以 Rust 为首选实现方案，不做特定客户端适配或验收。Qoder/WorkBuddy 可行性探查应与基础能力开发并行，按协议能力分别标记文本、工具和图片支持情况。

| 阶段 | 工作 | 可交付结果 | 结束条件 |
|---|---|---|---|
| G0：协议证据与边界 | 固定公开协议文档与支持子集；核实 Qoder 模型接口；识别 WorkBuddy 模型接口或远端 Agent 接口；核对 Rust 依赖方案 | 后端能力表、脱敏请求/事件样例、待证实项 | 能说明每家工具执行方、登录方式、会话状态、取消与用量；缺证据标 unknown |
| G1：最小纵向闭环 | Rust/Tokio/Axum 服务、Request/Event、Chat 入口、兼容 API 后端、SQLx SQLite、最小后端配置页 | 一个官方后端完成文本与工具往返，可持久保存配置 | 通用 HTTP 驱动 echo 工具声明→调用→结果→续答；重启恢复；中断不伪造完成 |
| G2：协议覆盖与官方网关 | Messages、Responses HTTP；三家预设；手填模型；能力目录；协议错误处理 | 三入口连接多个官方网关 | 三入口按支持矩阵完成跨 wire 转换；不支持的原生字段有明确反馈 |
| G3：单号私有适配器 | Qoder 单号；WorkBuddy 单号；凭证刷新；版本化信封与原生事件解码 | 两家独立适配器或明确的受限模式说明 | 两轮工具闭环、流式/非流式、会话隔离、鉴权过期、取消与恢复得到真实证据 |
| G4：auto 与账号池 | 候选准入、优先级、三种排序策略、会话绑定、冷却、费用边界、可选 CredentialSelector | 一个 auto 名称可在合格候选中选取，并解释结果 | 能力不匹配不误选；并发租约正确；只在允许条件下切换；未知执行结果不重放 |
| G5：任务与完整 GUI | 可选签到、额度同步、幂等任务、请求记录、配置备份、前端嵌入打包 | 个人可安装和配置的完整版本 | 停启模块、过期凭证、任务崩溃恢复、数据库备份、协议调用路径闭环 |

G0 对私有后端的发现不阻塞 G1/G2。G4 可以先用官方网关验证，但完整首版包含 G3：如果 WorkBuddy 的模型原生能力未成立，应明确尚未完成该需求，不能以“已经有菜单项”代替支持。

不在可行性未知时承诺“几天完成”。实际估算需依 G0 的协议证据、账号可用性、协议支持范围与 Rust 实现成本制定。

## 2. 各阶段任务拆分

### G0：确认事实源

- [ ] 固定 Chat Completions、Responses、Messages 的公开协议资料与查阅日期；建立支持字段、SSE 事件、错误和不支持能力表，不列客户端品牌/版本。
- [ ] 核实 Rust toolchain/MSRV、Axum/Tokio/Reqwest/SQLx 兼容版本及必需 feature；在实施阶段提交 Cargo.lock，验证 SQLite bundled 与静态前端打包。
- [ ] Qoder：单账号授权、模型 ID 和实际 wire、外部 tools 与 tool_choice、两轮工具结果回传。
- [ ] WorkBuddy：合法账号登录、模型列表/模型调用位置；确定是否接受外部工具、是否服务器自行执行动作、是否要求客户端常驻。
- [ ] 两家：检测 token 失效、模型排队、额度耗尽、取消、账号和地区隔离。
- [ ] 签到仅在存在真实领取接口与活动窗口证据时进入开发；额度单位、刷新时间及是否允许超额计费分别记录。
- [ ] 存脱敏契约样例，绝不把 token、Cookie、设备凭证或完整私人对话提交到仓库。
- [ ] 源码复用查许可与授权；默认独立实现，已有桥接服务可作黑盒对照。

### G1 / G2：协议与官方后端

- [ ] 用 Rust struct/enum 确定 Request/Event/Capabilities/Error 契约和终态状态机。
- [ ] 单 Cargo package 内分模块，实现 Send/Sync 后端 trait 与可取消事件 Stream；避免早期拆分大量 crates。
- [ ] 明确请求 guard、CancellationToken、任务追踪和有界 channel 的生命周期；覆盖响应流丢弃后的取消与本地许可释放。
- [ ] 实现统一工具 call ID 与参数分片归并，区分正文/思考/usage。
- [ ] 先以一个兼容后端验证，再补 Chat、Messages、Responses 的编解码和协议特有错误。
- [ ] 对未知字段建立策略：无害元数据可忽略并记录，影响工具、历史或输出语义的字段必须表达或拒绝。
- [ ] 创建 SQLite 迁移、配置快照与脱敏导入导出；避免长期网络调用持有写锁。
- [ ] GUI 添加后端、检查目录、手填模型、触发测试、查看失败原因。
- [ ] OpenRouter/方舟/百炼按官方入口与区域接入，不硬编码临时免费政策。

### G3：私有后端

- [ ] 每家适配器独立拥有凭证准备、构造 body/header、解码事件与取消。
- [ ] 消息和工具每次显式重建/覆盖；不注入官方客户端自带工具定义。
- [ ] 账号 token 刷新互斥、版本检查与失败恢复；不重复旋转同一 refresh token。
- [ ] 复测纯文本和工具两种路径：文本能回复不视为编程兼容。
- [ ] 只实现远端 Agent 模式的后端单独标记，并退出工具型 auto 候选。

### G4 / G5：路由、模块与使用闭环

- [ ] auto 候选初始为空；显式付费选择；无候选或不满足能力时返回原因。
- [ ] 能力证据含 provider/model/account/wire/version 与时间，未知必需能力不放行。
- [ ] 建立有限 attempt 与错误归属，防止 core、adapter、HTTP client 各自重试叠加。
- [ ] 凭证池可替换为单账号策略；关闭多号模块不影响已配置后端本身。
- [ ] 预算预留/结算并发正确；未知账单保留待核对，不当作 0。
- [ ] 签到按活动周期幂等、持久化任务；提交断线先查询，不能确认则暂停重放。
- [ ] 内嵌 GUI、个人 key、管理解锁、请求元数据与备份；单数据目录限制一个活动进程。

## 3. 验证矩阵

用可控制的协议假后端验证边界，用真实账号验证厂商接口。假后端通过不等于真实供应商兼容；真实验证需要用户可用账号，届时再完成，不在本轮规划中发请求。

| 类别 | 必测行为 | 通过证据 |
|---|---|---|
| 协议契约 | Chat/Responses/Messages 分别解析与输出；跨 wire 对照 | 用语义断言比较内容、block 顺序、tool ID、终态；不只比 HTTP 200 |
| 工具 | 空 tools、none/required/指定函数；并行分片；非法 JSON；截断 | 未声明的工具不出现；参数未完成不报成功；结果对应正确调用 |
| 多模态 | 图片直通；目标不支持图片 | 正确输入或明确拒绝，不静默删图 |
| 流与取消 | 跨字节块 SSE/UTF-8；上游 EOF/错误；下游断开；慢消费；长时间排队 | 有界内存、请求 task 回收、取消传播、无假成功、无两次响应开始 |
| auto | 候选空；能力未知；全部冷却；费用不符；上下文超限 | 返回逐项原因；不扩大费用权限、不截断历史 |
| 会话 | 无状态全历史迁移；opaque/Agent session 绑定；无 session ID | 可迁移的才切换；不同会话不串号；不猜测相同首句即同会话 |
| 重试 | 请求未发出；上游已受理无输出；已有工具片段 | 可重试边界明确；Agent execution_unknown 不重放 |
| 账号/预算 | 并发抢额度；同时刷新；中断后的租约释放 | 刷新单次、配额预留原子、未知账单保留 |
| 签到 | 同周期并发；成功后重启；POST 后崩溃；停用模块 | 无可确认的重复领取；unknown 需要查询或人工处理 |
| 存储/GUI | 配置事务失败、导入冲突、删除被引用后端、备份恢复 | 旧配置持续可用；引用不悬空；无凭证泄漏 |
| 协议端到端 | 通用 HTTP/SSE 测试驱动三入口，各完成文本和工具往返 | 字段、事件顺序、call ID、终态与错误符合支持契约，不依赖特定客户端 |
| Rust 构建质量 | 格式、静态检查、编译、契约测试与目标平台打包 | 在实施阶段运行 cargo fmt/clippy/test；无需本轮创建空 Rust 项目 |

路由预演只检查策略，不进行实际生成。主动连通测试可能消耗额度，由用户从 GUI 触发；无副作用工具验证只调用固定回显工具。

## 4. 完成口径

“首个完整版本完成”须同时满足：

1. 三种入口的声明兼容范围通过通用协议验证；未实现字段/端点明确列入限制，不附加指定客户端验收条件。
2. OpenRouter、方舟、百炼的目标模型可配置并完成实际调用。
3. Qoder 与 WorkBuddy 有真实接入证据；若受限为 Agent 会话模式，需用户接受该范围变化后才可按调整目标验收。
4. auto 的能力/费用边界与可解释记录闭环；账号池、签到可独立关闭。
5. 普通用户能通过 GUI 完成添加、恢复登录、路由设置和问题定位，无需直接改数据库。

## 5. 本轮交付与下一步

本轮已提供功能规划、架构提案和实施顺序，没有实现运行服务、连接账号或部署。

当前推荐为 Rust 服务、浏览器 GUI、SQLx SQLite 唯一事实源、trait 注册的进程内可选模块、规则型 auto（主动选候选、能力优先、付费显式开启）。协议契约是验收依据，不考虑具体客户端。若 auto 后续增加任务难度分析，应另加可观测策略，不在底层偷偷加入额外 LLM 调用。
