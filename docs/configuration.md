# 服务启动配置

Auto 的会话分散、排序策略、模型预算和比较范围见 [Auto 路由](./auto-routing.md)。

Gateway 共享重试信用已移除。单请求总尝试次数和时限继续生效，额外生成提交与首次提交共用服务 QPS；QPS 为 0 时不限速。旧 v1 设置中的重试信用字段会被忽略，不再显示或参与运行。

插件、版本化配置、权限密钥、CLI 与 MCP 见 [管理说明](./management.md)；当前模块边界见 [架构](./architecture.md)。服务配置以 SQLite revision 为事实源，声明文件只用于计划输入。

MonkeyCode 官网登录、三协议模型网关、积分查询与每日签到见 [MonkeyCode 接入](./monkeycode.md)。

## 网关调度与恢复

在「设置与接入 → 网关调度与恢复」保存预算、时限、容量与分配权重。
客户端统一指定 `auto`：先按费用和额度可信度分层，再按优先级，
同级结合倍率与负载分散。旧 `auto:*` 名称兼容调用并归一到相同规则；
`auto:free` 始终禁止付费后备。显式模型保持指定服务并分散其内部账号。
“允许付费及费用未知的服务作为后备”默认关闭，开启后只在主池没有合格可用目标时使用。

设置通过统一配置服务保存到 SQLite 配置 revision，并投影到 `gateway_settings` 兼容表，保存后热加载；
在途请求保留本次设置，已有绑定、冷却、容量租约和限频计数不被清空。连接时限通过重建
聊天客户端生效。配置导出包含可选 `gateway` 字段；旧 v1 包缺少该字段不会覆盖现有设置。
旧 `default_auto_spread` 字段不再使用，读取旧设置时忽略；它不会转为付费后备授权。

| 设置字段 | 默认值 | 含义 |
| --- | ---: | --- |
| `auto_allow_paid_fallback` | false | 主额度池无可用目标时允许付费及费用未知后备；可能产生额外费用 |
| `max_attempts` | 4 | 单请求总尝试预算，含适配器内部再次提交，范围 1–16 |
| `total_timeout_ms` | 600000 | 元数据读取、等待、退避、启动与完整流总时限 |
| `connect_timeout_ms` | 10000 | 聊天客户端连接时限 |
| `startup_timeout_ms` | 60000 | 每次响应头及首个有效生成事件等待上限 |
| `idle_timeout_ms` | 120000 | 流事件空闲上限，仍受总时限约束 |
| `backoff_base_ms` / `backoff_cap_ms` | 250 / 5000 | full jitter 退避基数与上限 |
| `queue_timeout_ms` / `queue_capacity` | 10000 / 128 | 容量及服务 QPS 等待时限与队列上限 |
| `group_ttl_ms` / `group_capacity` | 1800000 / 4096 | 路由绑定保留时间与组数上限 |
| `targets` | {} | 后端及 `后端/账号` 的 capacity、weight 覆盖 |

默认后端并发容量 16、账号并发容量 4、权重 1。权重用于同负载时的新组分配，
不是保证每个后端收到相同请求数。服务优先级在服务高级配置中设置；
同费用/额度层内数值较小者优先，同值参与分摊。容量覆盖示例：

```json
{"backend-a":{"capacity":16,"weight":2},"backend-a/account-1":{"capacity":2,"weight":1}}
```

`GET /api/gateway` 返回 `settings` 与 `runtime`，包含在飞负载、活跃组、
等待数量和局部冷却。`PUT /api/gateway` 接收完整设置对象；
省略字段使用默认值，推荐先 GET、修改所需字段后 PUT。两者采用现有管理鉴权。
界面保存时会保留请求期间新增的编辑。运行状态不含会话正文和凭证。

新设置不是成功率承诺：只有可证明未执行的错误才自动恢复。分组指纹和绑定本期
仅在内存，重启后重新推断，旧请求记录仍保留。应使用完整历史请求；
`previous_response_id` 等依赖远端增量状态的请求仍不支持。

## 每个服务的 QPS 限制

在「服务接入 → 添加或编辑服务」设置 **服务 QPS 限制**。字段为
`services[].policy.qps`，整数范围 0–10000，默认 0 表示不限。
每个服务的所有模型和账号共享滚动一秒窗口；例如 QPS=2，任意连续一秒
最多允许两次生成准入。Auto、指定模型和适配器内部生成重试共用此计数，
登录、目录、额度和签到请求不计入。

新 Auto 会话避开已达限额的服务，仍遵守费用许可；健康的原会话绑定等待额度，
不因本地限频迁移。等待与容量共用 `queue_timeout_ms` 和 `queue_capacity`，
限频等待超时返回 HTTP 429（`gateway_qps_timeout`）及 `Retry-After`；
总时限先到返回 504，队列满仍返回 503。

限额保存后热加载，无需重建登录连接。热更新保留最近一秒计数，
包括从不限改为有限或降低限额；在途请求保持捕获的策略。未提交预占在取消或
预算拒绝时退款。计数只在内存，重启后重新累计。

配置保存会验证整份合并配置。已有服务中的非法字段可能阻断其他服务和网关保存；
错误会同时给出字段路径、服务 ID 和插件名，按对应插件 schema 修正。

## 每十二小时自动更新账号额度

服务端默认开启额度自动更新，支持 Qoder、WorkBuddy、AutoGLM、MiniMax Code 与 MonkeyCode。
首次启动且没有更新记录时立即查询，随后每 43,200 秒更新一次；调度误差不超过约一分钟。
仅查询已启用服务的启用账号；每个查询最多等待 30 秒，最多并行四个账号。
单账号失败显示未知，其余账号继续更新，不把失败当成零余额。

额度快照及最近、下次更新时间持久化在 SQLite 中，服务重启沿用计划；
停机期间错过的更新在启动后执行一次，关闭浏览器不会停止后台更新。
手动点击「更新账号额度」仍可立即查询，完成后将下一次自动更新安排到十二小时后。
手动和自动共用串行批处理，并发手动请求复用同一批结果。

控制台「服务接入」显示最近和下次更新，首屏及可见页面每分钟只读取本地缓存，
不会因此重复查询厂商，也不重置正在编辑的配置或试聊。
`GET /api/quota` 保留手动更新语义；`GET /api/quota/cached` 读取持久缓存和
`auto_refresh` 状态，两者均使用现有管理鉴权。缓存不包含账号凭证，
人工更换凭证、停用或删除账号后旧快照失效，自动令牌续期保留同一钱包快照。

Auto 路由复用此持久缓存，生成请求不再重复查询厂商额度。超过十二小时或厂商重置
时限的余额作为未知；明确额度拒绝只失效该账号的旧快照，并进入局部冷却。
余额是准入参考，正余额不能保证足够完成一次生成，也不代表积分已预占。

## 一键签到所有账号

在 **任务** 页点击 **一键签到所有账号**，为已启用且支持签到的账号执行签到。
同一渠道（后端类型，例如 WorkBuddy）的账号串行执行：第一个立即执行，
其余账号在前一个结束后独立随机等待 **5–15 秒**。同厂商的多个服务配置也归入同一渠道。
不同渠道分别推进；随机等待不持有任务领取锁。

执行由服务端后台批次负责，关闭页面不取消任务，刷新页面可继续查看逐账号进度和结果。
重复点击或并发启动请求返回当前批次，运行期间页面禁用重复启动和单服务签到按钮。
单账号失败不会阻断其余账号；延迟期间被停用、删除或改换渠道的账号会跳过。
结果写入已有任务记录；外部动作前保存执行意图，服务中断后的未知领取禁止重放。
批次进度仅保留当前进程的最近一次，重启后通过持久任务记录核对已执行结果；
未执行的剩余账号不会自动恢复批量任务。

管理接口 `POST /api/tasks/checkin-all` 启动或返回运行中的批次，
`GET /api/tasks/checkin-all` 查询最近批次。两者均需现有管理鉴权，
返回 `run`、`delay_min_seconds=5`、`delay_max_seconds=15`；
批次包含逐账号状态、随机间隔、消息与可确认奖励。
一键签到与自动签到开关独立，自动任务关闭时仍可手动执行。

## 页面设置自动签到

在 **任务 → 自动签到** 中设置开关、每日开始时间和随机范围，点击 **保存设置**。
所有时间使用北京时间（`Asia/Shanghai / UTC+8`），不受电脑或浏览器时区影响。
例如 `10:00` + `60` 分钟表示每天在 `10:00–11:00` 内为各启用账号独立随机；
`0` 分钟表示固定时间。结束时间不能超过当天 `24:00`。

配置及各账号今天、明天的随机结果保存到现有 SQLite 数据库。
重复刷新和服务重启不会重新抽签；修改设置会重新安排未执行的计划，
执行过的账号当天不再自动执行。相同设置重复保存也不改变计划。
在窗口内首次开启会从剩余时间抽签。窗口结束后超过约 1 分钟仍未执行时，
计划标记为错过，等待次日；代理服务需保持运行，关闭网页不影响后台任务。

每账号每天最多一次自动尝试。失败、跳过或结果未知不会自动重试；
失败可在记录中核对后手动处理，未知结果禁止重放。
进程中断时正在执行的计划恢复为未知，避免无法确认结果的领取再次发送。
任务页显示各账号的下一次执行时间；自动关闭时显示计划预览。
调度每 15 秒检查一次，也会在保存设置或增删账号后立即唤醒，允许约 1 分钟误差。

`GET /api/tasks/checkin-schedule` 返回 `settings`、`timezone`、`running`、
`last_error` 及 `next_runs`。`PUT` 接收
`{"enabled":true,"time":"10:00","random_minutes":60}`，需现有管理鉴权。
`FMP_CHECKIN=1` 仅作为数据库首次创建该配置时的开关初值；
已有页面配置优先于环境变量。备份固定数据目录可保留设置及计划，
现有服务/账号 JSON 导入导出不包含签到调度设置。

## MiniMax Code 接入

控制台「服务接入 → 添加服务 → MiniMax Code」使用独立设备 OAuth，
完成官方网页授权后自动保存账号，再同步模型目录。国内与国际区域使用独立登录域名。
无需安装客户端或从客户端提取凭证。接口与验证边界见 [MiniMax Code](./minimax-code.md)。

## AutoGLM 接入

控制台「服务接入 → 添加服务 → AutoGLM」选择国内或国际区域。
国内通过代理提供的独立短信页面登录，国际通过官方 Z.ai / Google 授权及本机回调登录。
成功后账号自动保存；每次登录使用独立设备 UUID 和 600 秒会话，
关闭等待窗口、停用服务或变更登录配置会取消未完成授权。
已有凭证仍可手工导入，支持自动续期、积分查询、目录同步及每日签到。
此后端不执行输出硬限制；Auto 需要目录输出上限或显式的
`options.routing.provider_output_reserve`。完整说明见 [AutoGLM](./autoglm.md)。

## 请求文件记录与轻量 Trace

三个推理入口均保存请求元数据，默认保留最近 **1000 条**。正式服务使用
`FMP_DATA_DIR/requests.jsonl`（默认 `.fakemodelproxy/requests.jsonl`），每行一个请求。
进程启动会读取文件；旧记录超出容量时裁剪，未完成记录恢复为 `interrupted`。
保留范围按请求进入顺序决定，较早请求的迟到终态不会重新进入保留范围。

```sh
FMP_DATA_DIR="$HOME/.fakemodelproxy" FMP_RECORD_CAPACITY=1000 ./fakemodelproxy
```

`FMP_RECORD_CAPACITY` 只接受正整数，修改后重启生效。数据目录应使用固定路径；
相对路径随启动工作目录解析。请求开始、候选调用和最终状态通过同目录临时文件、
flush/fsync、原子 rename 和目录 fsync 更新正式 JSONL，不依赖进程退出时保存。
临时文件只用于原子替换，不作为记录存储。每次关键更新重写最多 N 条；默认容量适合个人低并发，
没有额外数据库、OTel SDK、Collector 或写入队列。一个数据目录只供一个代理进程使用。

启动无法读写文件时阻止启动；运行中写失败会在日志、`GET /api/records` 的
`persistence.last_error` 和控制台显示。此时界面可能包含未落盘的数据，后续成功写入
会重新保存完整保留范围。损坏 JSON 行会跳过，启动日志与
`recovered_invalid_lines` 显示数量；有效行仍恢复。不要运行中手动编辑文件。

记录含模型、协议、请求 ID、耗时、首个归一事件耗时、上游候选尝试、终止原因、
上游提供的 Token 用量及错误分类。缺失用量保持未知，不估算。原始错误消息可能
回显敏感内容，因此只保存错误码与状态；对话正文、工具参数、凭证及任意请求头不落盘。
会话插件只读取白名单字段：`x-fmp-session` 与 MiniMax Code 原生
`X-Mavis-Session-Id`，要求唯一、非空、不含控制字符且最多 256 字节。
`client` 和 `session` 保存客户端、关联来源与明确/推断类别，不保存其他头。

请求规模分别记录：`request_body_bytes` 为 handler 已读取的 body 字节数，
`request_body_complete` 仅正常读到 EOF 时为 true；
`request_content_length` 为可解析的客户端声明长度，
`request_body_limit_bytes` 为本次生效上限。413 会停止继续读取，
已读字节可能仅为总请求的一部分；不能据此推断完整体积。
这几个字段在 JSON/413 拒收时也可用，不保存请求内容。
解析成功后补充 `message_count`、`image_count` 与 `image_url_bytes`
（含 base64 data URL 的字节总量），工具结果图片包含在内。
旧记录缺少这些字段时保持未知，不解释为零。`input_chars` 仅统计消息文本字符，
不等同于请求字节数或模型 Token。

无可用路由时，`routing_rejections` 保存有界的本地排除依据和预算数值，
即使没有发起上游调用也可定位上下文拒收。控制台请求详情展示上述计数及原因。
请求体积上限和模型上下文准入独立，放宽体积上限不能让无限累积的截图历史通过。

`running / ok / error / cancelled / interrupted` 分别表示进行中、完整输出、
失败、响应未读尽便被取消、上次进程退出时未完成。HTTP 状态与流中上游错误状态独立：
流中失败可记录 HTTP 200、outcome=error、upstream_status=429。`ok` 表示服务端
完整响应已交给传输层，不能证明客户端已收到或消费。断电后的记录只反映最后一次成功同步状态。

关联遵循 [W3C Trace Context](https://www.w3.org/TR/trace-context/) 版本 `00` 的
`traceparent` 格式，并参考 [OpenTelemetry Traces](https://opentelemetry.io/docs/concepts/signals/traces/)
的 trace/span/parent 模型。JSONL 是本工具的审计格式，不是 OTLP。

- 入站有效 `traceparent: 00-<32位trace-id>-<16位parent-span-id>-<2位flags>`：
  继承 trace ID、记录父 span，创建本次请求的新 span。
- 不传或格式非法（含全零 ID、重复头）时创建独立新 trace；当前只接受版本 `00`。
  响应返回 `x-request-id` 和本次 span 的 `traceparent`，错误响应也返回。
- auto 的每个实际候选调用生成子 span，失败后换后端会保留尝试顺序与结果。
  子 span 仅在本地记录，不向厂商发送追踪头；不保存 `tracestate` 或 `baggage`，所有请求均记录，
  flags 仅回传，不控制采样。
- 一条调用链中的后续请求可携带上一响应的 `traceparent`，形成父子关系；
  同一父操作的并行请求应共享父 span，各请求生成独立 span。
- 已有 `x-fmp-session` 调用继续分组；MiniMax Code 的原生会话头自动生成
  `minimax_code:<客户端ID>` 分组，不需要客户端增加 FMP 头。
- TRAE 使用 `/clients/trae/v1` 地址选择 FMP 内插件，无需修改客户端代码。
  只有完整历史延续 FMP 已交付的实际输出时才推断关联。新起点、连续匹配与
  歧义拆组分别保存 `history_new / history_continuation / history_ambiguous`，
  均为 `confidence=inferred`，不是 TRAE 原生 SessionID。
- `user`、`metadata.user_id`、相同首句、相同模型、请求时间与连接复用不构成会话证据。
  推断键用于记录及账号分组，不充当厂商侧会话 ID。明确头也只标识客户端组；
  绑定独立持有厂商会话 UUID，迁移或过期后更换。

“设置与接入 → API 接入 → 客户端”可复制专用 Base URL。通用 `/v1` 自动识别
MiniMax 原生头；`/clients/minimax-code/v1` 也支持三协议和模型目录。
TRAE 请求若明确自报 TRAE User-Agent，或携带 `hertz + custom_responses_compatible + aha`
组合，通用地址也会选择插件。这只选择解析器，不证明身份；不能依赖客户端必定
发送品牌 UA，因此配置专用地址是稳定的选择方式。

TRAE 指纹索引保存在内存，容量跟随记录容量、24 小时过期，只保存带实例随机密钥的
历史和输出摘要。请求正文、输出、图片与工具参数不在索引或记录文件中保存。
历史压缩、截断、改写或 FMP 重启可能导致拆组；有唯一完整工具锚点时允许延续，
没有锚点则拆组。旧记录的分组仍从文件恢复。
复制完整历史后另开对话可能被推断为延续，独立摘要调用也可能无法归组。
没有真实会话标识时，这些情况无法仅靠服务端请求内容保证准确。

控制台请求详情支持同 Trace / 同会话查看，以及上游尝试。API 支持精确筛选：
`GET /api/records?trace_id=<id>`、`GET /api/records?session_id=<id>&limit=100`。
也支持 `client=trae|minimax_code`、`session_confidence=explicit|inferred` 精确筛选。
响应含全量 `total`、筛选后 `matched` 和实际文件状态。列表默认返回当前保留范围；
已被裁剪的父节点可能不存在，查询结果不是完整的分布式追踪。

## 查看每个模型的 Token 限制

在控制台的 **模型与调试 → 模型目录 → 参数** 中查看上下文窗口、最大输入、最大输出及默认 / 可选窗口档位，并复制客户端模型配置参考。**设置与接入 → API 接入** 的模型选择下方也提供入口；服务详情中的模型目录支持查看同一份参数。

字段含义：

| 字段 | 含义 |
| --- | --- |
| `context_window` | 上游明确声明的总上下文窗口；存在档位时显示目录最大档位 |
| `max_input_tokens` | 上游声明的最大输入量，不能等同于总上下文窗口 |
| `max_output_tokens` | 上游声明的最大输出量，不等同于本次请求的 `max_tokens` |
| `context_tiers` | 上游提供的可选档位，`tokens` 为原始 Token 数，`is_default` 标记默认档位 |

数值只取自目录明确字段或配置，不按模型名称推测。缺失显示“未知”，不是无限制。旧缓存仍可显示原有值，重新同步目录会补齐上游提供的新字段。`GET /v1/models` 在每个模型条目的 `token_limits` 中返回这些元数据，并保留旧 `capabilities.context_window` 字段以兼容已有调用方。后者在旧目录中可能表示默认档位或输入上限，新接入应优先读取 `token_limits`。

外部客户端使用持久调用名称（如 `qoder-qwen4-max`），可在模型参数页复制和编辑。名称不会随显示名变化，改名后旧名称继续兼容；完整规则见 [模型调用名称](model-names.md)。

复制的 JSON 是**客户端模型配置参考**，需映射到具体客户端的模型配置字段，不是标准聊天请求体。显示目录参数不会改变聊天请求，也不会自动切换上游档位。

- Qoder 目录可提供多档窗口，但当前适配器固定声明 `max_input_tokens=180000`，不会根据客户端配置切换档位。不要把目录最大档位直接当作当前请求可用输入量；180000 也只是请求声明，不能据此保证上游实际容量。
- WorkBuddy 的 `maxInputTokens` 作为输入上限展示；若目录未提供总窗口或输出上限，这两项保持未知。
- AutoGLM 不透传请求中的 `max_tokens`；Auto 使用单独的上游最大输出预留，未知时排除候选。
- OpenAI 兼容网关已配置白名单时使用现有配置；只有目录响应明确提供限制字段时才读取它们。

## 对话请求体上限

Chat Completions（`/v1/chat/completions`）、Responses（`/v1/responses`）和 Messages（`/v1/messages`）默认允许最多 **64 MiB（67,108,864 字节）** 的请求体。三个入口使用同一上限，完整 JSON 中的历史消息、工具声明、工具结果和图片数据都计入字节数。

长对话由客户端在后续请求中重复发送历史内容。此前这些入口使用 Axum 默认的 2 MiB 限制，超过后会在请求解析前返回 `Failed to buffer the request body: length limit exceeded`。现在允许更大的完整历史，代理不裁剪或改写历史内容。

通过环境变量调整上限，设置后重启服务：

```sh
FMP_MAX_REQUEST_BODY_MB=128 ./fakemodelproxy
```

`FMP_MAX_REQUEST_BODY_MB` 的单位为 MiB，只接受正整数。空值、零值、小数、负数或转换为字节数时溢出的值会阻止启动。启动日志显示最终生效的 `max_request_body_bytes`。

超过配置上限时仍返回 HTTP 413，但错误采用入站协议的 JSON 格式，说明本地上限以及调整方法。OpenAI 两个入口使用错误码 `request_body_too_large`；Messages 使用 `request_too_large` 错误类型。未提供 `Content-Length` 的分块请求也会按实际接收字节数检查。

管理和登录接口保持原有的独立请求体限制。

请求体大小与模型上下文长度是两个限制。提高代理上限不会提高模型的 token 上限；长对话仍需由客户端压缩历史或管理上下文。由于入口缓冲完整请求，调大上限也会增加并发请求的内存需求。
