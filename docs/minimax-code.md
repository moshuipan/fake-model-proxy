# MiniMax Code：独立 OAuth 接入

实现日期：2026-11-19；主控制台接入更新：2026-11-20。

## 使用

主控制台：<http://127.0.0.1:8317/>。在「服务接入 → 添加服务」点击 **MiniMax Code**，
选择区域并保存。点击「登录账号」完成官方网页授权，账号自动保存；然后同步目录，
从「模型与调试」复制模型调用名称。无需另开预览服务。

早期 `8318` 预览使用独立数据目录 `.minimax-oauth-preview/`；其账号不会自动迁入主实例。

其他部署中，添加服务时选择预设 **MiniMax Code（独立 OAuth）**，选择国内站或国际站，保存后登录即可。代理可以运行在服务器，授权网页可以在另一台电脑打开，无需桌面客户端、localhost 回调或额外社区代理进程。

对外地址分别为 `/v1/chat/completions`、`/v1/messages` 和 `/v1/responses`。模型名称以同步后控制台实际显示的持久别名为准。

## 授权与保存

- 后端类型为 `minimax_code`，选项为 `{"region":"cn"}` 或 `{"region":"global"}`。
- 国内授权域为 `account.minimax.cn`，国际授权域为 `account.minimax.io`。
- 使用官方公开客户端 `mcode-public`，scope `agent.default`、audience `agent-backend` 和随机 PKCE S256。
- 同时兼容标准 `device_code` 格式与官方 `user_code` / `expired_in` 格式；服务端执行有截止时间的轮询并处理 `authorization_pending` 和 `slow_down`。
- 每个授权窗口都有独立随机会话，查询和取消同时验证服务 ID 和会话 ID。
- 访问令牌和刷新令牌只保存到代理账号数据库；管理接口和前端不返回令牌。未读取桌面客户端凭证、broker 或登录状态。
- 区域固定在凭证内；服务变更或停用后的迟到授权不能写回账号。

凭证刷新前先写 SQLite 围栏。收到新令牌后先暂存，再通过比较原凭证的事务提交。重启可以恢复已暂存的成功结果；超时、5xx 或坏响应导致刷新结果未知时不重复发送旧刷新令牌，需要重新 OAuth 授权。

账号库和刷新暂存表包含凭证，备份应保护整个数据库。不要把包含密钥的配置导出提交到仓库。

## 模型、额度与签到

聊天直接访问所选区域的 MiniMax Code Anthropic Messages 网关。原生解码支持文本、工具调用、推理增量、usage、CRLF 和跨分片 UTF-8；终态前断流会报错，不当作成功，也不自动重放结果未知的生成请求。

动态目录以官方当前响应为准，包含上下文、输出上限和可选上下文档位。失败时可以暂用最后一次成功快照，不创建硬编码模型。目录档位是元数据，当前没有新增切换 1M 上下文的专属请求参数。

Chat Completions 和 Messages 输出推理正文。Responses 沿用本项目当前契约，输出文本、工具和用量，不输出推理正文，也不提供官方加密推理状态的往返能力。

积分读取账号账本，仅汇总未过期批次。数据库 API 的金额单位为 `0.01 积分`，控制台换算成积分显示；它不代表套餐剩余百分比，也不能作为单请求消耗。

签到已注册到现有任务系统。只在面板明确标记可领取时提交；领取响应缺少有效奖励或结果未知时，不报告成功。自动调度默认关闭，当前预览没有执行真实签到。

## 验证边界

已完成：

- 官方国内设备授权握手返回有效短码与官方授权链接；未确认真人授权。
- 内置浏览器验证预设选择、区域显示、保存服务、展示短码和取消授权。
- 本机假上游验证两种设备响应、PKCE、等待、多窗口隔离、取消、配置变更拒收、刷新锁竞争、刷新结果未知围栏、SQLite 重启恢复、账号删除、动态目录、积分小数与过期批次、签到响应校验及三协议转换与断流。
- Rust 全量测试和控制台回归覆盖独立 OAuth、模型发现及三种 Auto；路由行为见 [Auto 路由](./auto-routing.md)。

尚未完成真实账号换票、真实刷新、真实生成、真实积分或签到，以及国际站端到端验证。独立 OAuth 会话是否与同一账号桌面登录互斥仍未实测，不能保证同账号并行会话不受影响。

## 本机重启预览

```sh
FMP_LISTEN=127.0.0.1:8318 \
FMP_DATA_DIR="$PWD/.minimax-oauth-preview" \
./target/debug/fakemodelproxy
```

先结束已经占用 `8318` 的预览进程，再执行；不要同时启动两个实例占用同一端口。正式部署继续使用项目原有的调用密钥、管理密钥和监听配置。
