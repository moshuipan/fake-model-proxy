# 请求记录与客户端会话关联

请求记录保存会话来源、匹配的前一请求及匹配规模，不保存对话正文、图片、
工具参数、指纹或凭证。`session_id` 是查询与调度分组键；`session.confidence`
区分客户端声明的 `explicit` 与内容连续性推断的 `inferred`。

MiniMax Code 的 `X-Mavis-Session-Id` 与合法的 `x-fmp-session` 是明确来源。
TRAE 专用入口 `/clients/trae/v1` 或已核实的客户端请求特征选择 TRAE 规则，
不把请求 ID、用户标识或时间接近当成真实 SessionID。

## TRAE 工具调用

个人版 TRAE CN 3.4.24 实测会把模型返回的工具调用 ID 替换为客户端自己的
随机 ID，并可能把助手文本和工具调用拆成连续的两个消息。会话指纹合并这些
助手消息，以工具名称和规范化 JSON 参数替代随机 ID，同时保持工具结果与
调用的配对及消息顺序。此规则只作用于摘要用临时消息，不修改发往上游的请求。

完整历史包含已交付输出且继续追加用户或工具消息时，选择最长匹配的完成
历史。请求详情的“匹配请求”因此指向最近可证实的前一请求，而非退回较早轮次。
相同首句不会合并。

历史被裁剪时，TRAE 锚点要求保留已交付的完整助手文本、全部工具调用及其
结果关联。只保留工具名称、相同文件路径或单个随机 ID 均不足以匹配。
完整历史或工具锚点匹配多个会话时，建立新组并记录 `history_ambiguous`。
相同文本和工具语义在多个会话中重复时同样保持歧义。

## 可复核记录

`session.evidence` 提供：

| 字段 | 含义 |
| --- | --- |
| `logical_messages` | 忽略 system/developer 并合并连续助手消息后的历史长度 |
| `matched_messages` | 完整前缀匹配长度；工具锚点恢复时为一条完整助手输出 |
| `matched_tool_calls` | 工具锚点包含的调用数，完整前缀匹配时为 0 |
| `candidate_groups` | 当前匹配依据对应的不同会话数；大于 1 时拆组 |
| `normalized_tool_ids` | 输入历史中经 TRAE 规则归一的工具调用 ID 数 |

控制台“请求详情”显示这些计数，前一请求仍在保留范围时可以点击打开。
旧记录没有 `evidence` 时保持兼容，不补造历史证据。

## 交付与边界

只有正常交付的完整响应可以发布连续性证据。流式响应须把协议终止事件交给
HTTP 传输层，排队完成、失败或提前取消不发布证据。三个协议共用这一生命周期。
明确会话可以进入上游会话机制；推断会话只用于 FMP 请求关联与调度分组。

索引在内存中保存带实例随机密钥的有界指纹，24 小时过期，容量跟随记录容量。
重启保留请求记录但清空推断索引。历史摘要、丢失完整锚点或复制历史仍可能拆组、
产生歧义或归入已有组。FMP 无法从缺少原生标识的请求中保证恢复真实 TRAE 会话身份。
