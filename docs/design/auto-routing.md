# Auto 路由

客户端统一选择 `auto`，模型目录、试聊和接入示例只展示“Auto · 自动额度池”。
目标是把多个免费/套餐额度来源组成一个有界、可恢复的生成服务。
倍率、余额、负载和优先级现在属于同一套决策过程，不再需要选择策略。

旧 `auto:priority`、`auto:multiplier`、`auto:quota`、`auto:spread`、`auto:cost`、
`auto:fast` 继续作为兼容名称接受，行为统一到 `auto`，同会话切换这些名称不会拆组。
`auto:free` 同样使用统一规则，但始终禁止付费后备。旧策略排序语义不再保留。

统一顺序：

1. 能力、上下文、输出预算、启用状态、冷却、硬额度和日预算准入。
2. 免费/已有套餐额度主池 → 付费后备 → 费用未知后备。后两类默认禁用。
3. 每个费用池内，已确认正余额或不限量优先，额度未知作为候补。
4. 同层按配置优先级，数值越小越优先；模型覆盖优先于服务优先级。
5. 同优先级在各自计费范围内选择有效倍率较低的候选，倍率未知作为同域后备。
6. 对剩余同级目标分散新会话：先服务再账号，按在飞比例、组数/权重、轮转游标。
   账号处于相同计费范围时，余额在负载和组数相同后用于择优；延迟只作末级参考。

先筛选实际可用容量与服务 QPS，再选最优层，因此主层全部冷却、耗尽、占满或达到限频时，新会话
会进入下一合格层；费用后备仍受开关约束。同组原目标健康但繁忙时有界等待，
不会因为别处余额更多或价格更低而每轮迁移。失败后按相同规则重新选择。

优先级不同意味着主备关系，相同意味着可以分摊服务。例如 A/B 设为 10，
C 设为 20：同费用/额度层内 A/B 分散，二者没有可用目标时使用 C。
若 A/B 的额度未知而 C 已确认可用，则 C 先进入候选层。
不同模型的能力与质量不等价，使用 `candidate_models` 设定可接受的模型范围，
需要质量分层时使用 `model_priority`，不要假设低倍率自动等于相同效果。

Auto 先检查模型能力、默认上下文档位、输入预算、输出预留、账号健康、
费用许可与日预算。已知余额耗尽的账号不参与候选，未知余额不按零处理。
Qoder 的实际输入预算上限为 180,000；目录最大可选窗口不作为当前生效窗口。
WorkBuddy 旧目录的窗口字段按输入上限解释。缺少输入和窗口信息的模型退出 Auto，
可通过明确的路由预算配置加入。

输入使用保守的 UTF-8 字节估算，包含文本、工具定义、工具调用与结果。
默认另预留 1,024 个 Token 用于适配和上游提示；输入余量为
`max(1024, ceil(输入估算 × 5%))`。这是保守估算，不是精确 tokenizer。
请求中任意历史消息包含图片时，只允许目录声明 `images=true` 的模型参与 Auto，
包括后端原生 Auto；纯文本请求可使用文本和视觉模型。各适配器按上游模型级布尔字段、
输入模态或官方任务类型同步能力，不凭模型名推断。
工具结果中的图片同样参与能力检查与图片预算：Responses 的
`function_call_output.output` 图文数组、Messages 的 `tool_result.content`
图文数组及 Chat 的 tool 图文消息均保留图片。base64 data URL 不按普通文本估算。
Messages 同一条消息中的多个工具结果拆成各自带调用 ID 的 tool 消息，
全部结果连续排列；普通正文保留相对次序，整体放在这些结果之后的 user 消息中。
不支持或损坏的明确图文块返回 400，不静默丢弃图片。
能力组合还必须满足适配器的 `validate_request` 表达限制，宿主配置不能覆盖。
Qoder 的当前私有封包仅在 user 消息中编码图片，含工具结果图片的请求会排除
该候选；显式 Qoder 调用同样在提交前返回 `image_role_unsupported` HTTP 400。
图片默认按每张 8,192 Token 预留容量，再叠加输入余量；这是容量估算，
不是图片 tokenizer 或对任意分辨率的硬保证。可用 `image_tokens` 调整，
显式 `null` 或 `0` 会禁止该服务的图片请求参与 Auto。
支持输出硬限制的后端，未指定输出上限时使用 8,192，并在上游请求中执行此限制。
请求指定的输出超过模型能力时排除候选，不缩小用户参数。
AutoGLM 官方 `input` 数组映射输入模态，目录 `maxTokens` 映射模型输出上限。
它不接受请求中的输出上限字段，Auto 使用目录声明的最大输出量，
或显式配置的 `provider_output_reserve`；两者都有时取较大值。两者都未知时退出 Auto；
请求中的 `max_tokens` 不能替代这项预留。显式预留必须覆盖上游可能的最大输出，
它是部署容量预算，不是上游输出硬限制。预演和审计用 `output_enforced=false`
标明这个边界。

倍率和余额默认只在同一服务计费范围比较；不直接比较不同厂商的裸积分数值。
跨计费范围由共同层级和负载分散决定，不用裸倍率比较。若多个服务属于已核验的
同一供应商、套餐和倍率基准，可在它们的后端选项中设置相同的
`routing.comparison_scope`；余额单位不同仍分开比较。此字段是用户声明，
不会自动换算币值或积分，也不证明不同厂商价格可比。

v2 服务中的调度策略示例；专属区域配置保留在 `config.options`：

```json
{
  "policy": {
    "qps": 2,
    "candidate_models": [],
    "model_priority": {"native-model-id": 10},
    "default_output_tokens": 8192,
    "provider_input_reserve": 1024,
    "image_tokens": 8192,
    "input_margin_tokens": 1024,
    "input_margin_percent": 5
  }
}
```

可选 `input_limit` 与 `context_limit` 与目录已有约束取最小值；
可选 `image_tokens` 覆盖默认的每张图片容量预留。`candidate_models`
为空继承模型白名单，也可指定原始模型 ID、内部地址或公开调用名称。
未配置模型优先级时继承服务优先级。每轮重新准入；无关配置更新保留现有绑定。
旧 v1 的 `options.routing` 会迁入 v2 的 `policy`；控制台的 QPS 输入直接保存到 `policy.qps`。

正式服务后台每分钟检查五分钟目录缓存，活动报价到期后失效；生成只读取快照，
不等待远程目录或余额查询。新服务可先在控制台同步目录，后台也会补齐目录缓存。
额度复用服务端十二小时持久缓存，超过有效期或厂商重置时限后作为未知；
明确额度拒绝会失效该账号的旧快照。后台批处理或手动更新可刷新余额。
独立构造、未接入 Store 的 Router 保留远端刷新兼容路径。余额用十进制定点比较，
MiniMax 保留百分之一积分单位；缺失和不完整的数据保持未知。
AutoGLM 钱包保留原始积分单位及最多十八位小数。
WorkBuddy 使用当前资源包的 `CycleRemainCapacity`，只汇总 `credits` 单位，
保留最多十八位小数，例如 `2118.80000012`，不先四舍五入成整数积分。
未知余额不当成零，最终调用固定选中的账号。

`X-FMP-Session` 或 MiniMax 原生会话头用于分组；未提供 ID 时按已完整交付的历史
与输出摘要推断。首条内容相同的两个新请求独立分组，歧义时拆组。TRAE 插件只为摘要
提取完整 `<user_input>` 包装内容，原始正文照常转发；相邻 assistant item 合并比较。
裁剪历史保留完整工具调用及结果关联时，可用唯一工具锚点延续。

Responses 的同轮正文和多个 `function_call` flat item 在入站时合并成一条
assistant 消息，工具结果保持在该调用批次之后；遇到结果或其他角色时结束合并。
这项归一影响实际上游请求，不只是历史摘要。三协议在生成前统一检查完整工具关联：
同一批次的每个调用必须有且只有一个连续结果，结果可以按 ID 逆序返回，
批次中不能插入普通 user/assistant 消息；后续回合可重新使用已完成的调用 ID。
孤立、错配、重复及缺失结果返回本地 HTTP 400（`invalid_tool_history`），
不产生上游尝试。诊断只包含归一消息位置与结构原因，不含参数或结果正文。

流式完整交付以协议终止帧被 HTTP 响应层读取为准：Chat 的 `[DONE]`、
Messages 的 `message_stop`、Responses 的 `response.completed` 或
`response.incomplete`。客户端读到该帧后停止读取，不再要求继续读取 HTTP EOF，
请求保留 `ok` 并发布历史摘要。上游生成完成或结束帧仅进入发送队列不构成交付；
中途取消、流中错误和缺少合法终止事件均不发布历史摘要。

同组原子预占并优先原目标。新组先比较后端、再比较账号的
`(in_flight / capacity, active_groups / weight, cursor)`；
模型多的后端不因此获得更多分配权重。显式模型只在指定后端的账号内分散，
普通容量繁忙有界排队。Auto 兼容名称共享绑定；显式模型与费用许可仍隔离，
配置版本不构成会话身份。
显式分组的厂商会话 UUID 由绑定独立拥有，同绑定保持稳定，迁移、过期或重启后重建；
推断组不传厂商会话 ID。分组、绑定与指纹本期仅在内存，重启后会重新分组和分配。
内容推断要求下一轮包含可唯一匹配的已交付历史或完整工具锚点；仅有相同首条输入、
摘要替换历史或缺少上一轮实际输出，不能保证延续。排查时检查上一轮 `outcome`
和下一轮 `session.source`，成功的完整历史延续应为 `history_continuation`。

调用前和启动缓冲内确认未执行的错误可在总预算内换目标。连接建立前失败、
明确账号权限/额度拒绝及安全限流可恢复；一般 408、5xx、发送后超时和未知执行不重放。
首个有效生成事件确认后才建立下游 SSE，HTTP 200 或 Usage 不冒充生成启动。
已输出内容或流中失败不切换、不拼接另一生成。缺少合法终止事件为失败，
正常 Finish 要等上游耗尽后才交付。客户端断开立即取消上游与容量等待，释放完整流租约。

账号、账号模型、后端模型与后端故障分别冷却，支持 Retry-After 秒数和 HTTP 日期；
冷却过期每个故障范围只允许一个探测，旧成功不能清除新故障。三个入站协议
和适配器内部 endpoint/auth 再提交共享单请求总尝试预算，所有生成提交遵守服务 QPS。
确认未执行的 429 之后，本次请求排除该账号的其他模型，继续选择其他账号或服务，
避免通过模型目录放大同一账号的提交量；跨请求冷却仍按原故障范围处理。
默认每请求最多 4 次尝试，包含首次提交和适配器内部重提；不再设置 Gateway 共享重试信用。
每个请求独立使用次数预算，跨模型、账号和内部重提的提交速率由服务 QPS 限制。
QPS 缺省为 0（不限），需要显式配置正数才能限速。
次数预算拒绝发生在再次提交前时，保持最近的 429 和已有 `Retry-After`，
启动前 deadline 仍返回 504，执行未知仍禁止重放。

并发容量默认每服务 16、每账号 4，租约覆盖完整流，不是上游允许并发数的声明。
已核实的账号并发限制通过 `gateway.targets["服务ID/账号ID"].capacity` 配置；
服务级限制使用服务 ID。繁忙请求默认最多等待 10 秒，等待超时和队列满仍属于
FMP 容量不足的 503。全部合格候选因 429 冷却时返回 429 与最早恢复时间；
服务 QPS 默认不限，所有模型、账号和内部生成重试共用滚动一秒计数。
新组避开已达限额的服务，原绑定等待窗口恢复；限频等待超时返回 429，
等待期间不消耗生成预算。本地限频不写入上游故障冷却；配置热更新保留窗口历史。
没有满足能力、费用、额度或配置条件的目标仍按实际排除原因返回 400 / 503。

当前上游未提供统一的单次积分消耗公式，预占状态为
`reservation_unavailable`。这是积分预占的限制；网关已有独立的并发容量租约，
审计 `reservation=capacity_acquired`。正余额不保证足够支付一次请求，也不承诺防止并发超额。
共享钱包不会把多个账号余额加总为一次请求可用额度。

控制台「模型与调试 → 预演自动路由」可输入估算量、输出预留、工具及图片需求，
查看账号、比较范围、倍率、余额、有效窗口及排除原因。请求记录的
`attempts[].routing` 保存费用池、额度层、优先级、预算、启动时间、迁移、
故障范围与恢复提示，不保存正文
或凭证。`generation_budget_used` 包含适配器重新提交消耗的预算；目标子 span 数与
实际 POST 数不是同一个指标，生成前检查失败也可能消耗一次准入尝试预算。
无可用目标时，`routing_rejections` 保存最多 128 个本地排除原因，
每项模型及原因最多 256 字符，包括输入、输出、窗口的具体预算数值。
这些请求可能没有 `attempts`，因此不能只检查上游错误状态来判断失败来源。

`GET /v1/models` 只发布一个 `auto`，虚拟模型不声明固定上下文窗口。
请求能力或上下文全部不兼容返回 400；资源/配置不可用返回 503；全部限流返回 429，
恢复时间已知时返回 `Retry-After`。启动前超时返回 504，流开始后的错误使用对应协议事件。
配置项、默认预算与管理接口见 [服务启动配置](../guides/configuration.md)。
